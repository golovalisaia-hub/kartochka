# Карточка

Мобильное веб-приложение для хранения скидочных карт. Карты остаются на устройстве и при входе могут синхронизироваться через отдельный проект Supabase `kartochka`.

## Возможности

- добавление вручную, сканирование камерой и распознавание фото;
- QR, EAN-13, Code 128 и оригинальные изображения неподдерживаемых кодов;
- поиск, редактирование, дизайн и резервные копии;
- установка как PWA и базовая работа без интернета;
- вход **по электронной почте и одноразовому коду из письма** — пароль не нужен;
- изолированное хранение карт каждого аккаунта благодаря PostgreSQL Row Level Security.

## Облако и вход

`config.js` содержит URL отдельного проекта и только публичный `sb_publishable_…` ключ. Никогда не публикуйте `service_role`, secret key или пользовательские токены.

Таблица `public.cards` и RLS применены к проекту `kartochka`; исходник миграции: `migrations/20260916_cloud_cards.sql`. Пользователь вводит почту, получает одноразовый код, вставляет его в приложение и входит. Первый успешный вход автоматически создаёт аккаунт Supabase Auth. Карты сохраняются через REST API с пользовательским токеном; запросы без входа не имеют доступа к таблице.

Для входа именно кодом в Supabase Email Template для Magic Link / OTP должен использоваться `{{ .Token }}`. Email provider должен быть включён. Этот параметр нельзя подтвердить из репозитория, поэтому перед публичным выпуском его нужно проверить в Supabase Dashboard. Для массового запуска нужен надёжный SMTP.

В облачном модуле есть локальный кэш на аккаунт: временная потеря сети или сбой обновления сессии не должны удалять кошелёк. При окончательно недействительной сессии локальные карты сначала архивируются под ID аккаунта и подмешиваются обратно при следующем входе того же пользователя. Неуспешная синхронизация помечается в интерфейсе как несохранённая.

Автоматические тесты проверяют код и работу с имитацией API на разных браузерных профилях; они **не** подтверждают реальную доставку писем, кассовые сканеры или синхронизацию на физических устройствах. Перед публичным запуском нужен отдельный реальный тест с двумя устройствами и тестовым аккаунтом без настоящих номеров карт.

## Локальный запуск

Запускайте через HTTP, а не прямым открытием `index.html`: `npx serve .`.
