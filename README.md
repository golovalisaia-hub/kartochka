# Карточка

Мобильное веб-приложение для хранения скидочных карт. Карты остаются на устройстве и при входе могут синхронизироваться через отдельный проект Supabase `kartochka`.

## Возможности

- добавление вручную, сканирование камерой и распознавание фото;
- QR, EAN-13, Code 128 и оригинальные изображения неподдерживаемых кодов;
- поиск, редактирование, дизайн и резервные копии;
- установка как PWA и базовая работа без интернета;
- регистрация и вход **по электронной почте и паролю** через Supabase Auth;
- изолированное хранение карт каждого аккаунта благодаря PostgreSQL Row Level Security.

## Облако и регистрация

`config.js` содержит URL отдельного проекта и только публичный `sb_publishable_…` ключ. Никогда не публикуйте `service_role`, secret key, пароли или токены пользователей.

Таблица `public.cards` и RLS применены к проекту `kartochka`; исходник миграции: `migrations/20260916_cloud_cards.sql`. Регистрация отправляет подтверждение почты, если это включено в Supabase. После подтверждения пользователь возвращается на сайт и входит с почтой и паролем. Карты сохраняются через REST API с пользовательским токеном; запросы без входа не имеют доступа к таблице.

**Проверка настроек в Supabase Dashboard обязательна:** Authentication → URL Configuration → Site URL и разрешённый Redirect URL должны указывать на `https://golovalisaia-hub.github.io/kartochka/`. Authentication → Providers → Email должен быть включён. Не отключайте подтверждение почты. Для массового запуска нужен надёжный SMTP.

Автоматические тесты проверяют код и работу с имитацией API на разных браузерных профилях; они **не** проверяют реальную доставку писем, кассовые сканеры или синхронизацию на физических устройствах. Перед обещанием полной надёжности проведите отдельный тест с двумя настоящими устройствами и тестовым аккаунтом, не используя реальные номера карт.

**Ограничение:** текущий алгоритм разрешения конфликтов синхронизации использует `lastUsed` и не гарантирует отсутствие потери изменений при одновременном редактировании на нескольких устройствах или нестабильном интернете. Не удаляйте сайт и не выходите из аккаунта при неподтверждённой синхронизации. Резервную копию сохраните отдельно.

## Локальный запуск

Запускайте через HTTP, а не прямым открытием `index.html`: `npx serve .`.
