# Фирменные материалы «Карточки»

Сюда кладутся **оригиналы владельца**. Ничего в этой папке не генерируется автоматически и не
пережимается: код только ссылается на файлы по имени.

## Какие файлы нужны

| Файл | Состояние | Параметры |
| --- | --- | --- |
| `welcome.mp4` | **есть** | 960×540, 20 к/с, 7,00 с, 140 кадров, H.264 без звука, 496 КБ |
| `welcome.gif` | **есть** | 640×360, 15 к/с, 105 кадров, зациклен, 3,3 МБ |
| `avatar-telegram.jpg` | нужен от владельца | квадрат, JPG, ≤ 5 МБ |
| `welcome.png` | не нужен | запасная статичная обложка |

Приветственная анимация готова. Оба файла сделаны из оригинального ролика владельца:
MP4 — копия видеопотока **без пересжатия**, GIF — конвертация с палитрой и дизерингом.

Бот берёт **MP4 первым**: это тот же ролик в полном разрешении 960×540 при 20 к/с, но весит
496 КБ против 3,3 МБ у GIF в 640×360 при 15 к/с. Telegram всё равно приводит GIF к MP4, так
что GIF остаётся запасным вариантом.

Целостность и реальное движение проверяются автоматически:
`node tests/branding-animation.cjs` декодирует GIF до пикселей собственным декодером и
сравнивает кадры, а MP4 разбирает по боксам контейнера. Переименованный PNG или сто
одинаковых кадров этот тест не пропустит.

## Как их использует код

**Аватар.** Ставится не кодом приложения. Порядок:
`@BotFather` → `/mybots` → `@KartochkaWalletBot` → `Edit Bot` → `Edit Botpic` → отправить
`avatar-telegram.jpg`. Telegram обрезает аватар в круг, поэтому по краям квадрата нужен запас:
логотип и серебристое кольцо должны умещаться в круг, вписанный в квадрат, иначе углы срежутся.

Проверить обрезку до загрузки:

```
node tools/avatar-crop-check.cjs assets/branding/avatar-telegram.jpg
```

Скрипт скажет, квадратный ли файл и какая доля логотипа срезается кругом, и положит рядом
превью `…-crop-preview.png` — слева квадрат, справа реальная круглая обрезка Telegram.
Исходный файл не изменяется.

Проверить, существует ли в актуальном Bot API метод для смены аватара ботом самостоятельно,
можно запросом `{"action":"brand"}` — он безопасно опрашивает живой API и возвращает вердикт
в поле `avatar.api_can_set`. Пробный вызов не передаёт файл и не может случайно сменить аватар.

**Анимация приветствия.** Бот ищет обложку по порядку:

1. `TELEGRAM_WELCOME_ANIMATION_FILE_ID`
2. `TELEGRAM_WELCOME_ANIMATION_URL`
3. `TELEGRAM_WELCOME_PHOTO_FILE_ID`
4. `TELEGRAM_WELCOME_PHOTO_URL`
5. `<адрес приложения>/assets/branding/welcome.gif`
6. `<адрес приложения>/assets/branding/welcome.mp4`
7. `<адрес приложения>/welcome.mp4`, `<адрес приложения>/welcome.gif`
8. `<адрес приложения>/assets/branding/welcome.png`, `<адрес приложения>/welcome.png`

Первый принятый Telegram источник запоминается. Файл передаётся как есть — ничего не
пережимается и не обрезается.

## Важно про доступность

Файл в GitHub **не значит** файл по адресу сайта. Telegram скачивает обложку по HTTPS сам,
поэтому адрес обязан открываться без авторизации. Пока `TELEGRAM_WEB_APP_URL` закрыт защитой
развёртывания (Vercel Deployment Protection), Telegram не получит ни обложку, ни приложение.

Проверить фактическую доступность: `{"action":"brand"}` возвращает `avatar.source_reachable`,
а `{"action":"diagnose"}` — состояние адреса приложения.
