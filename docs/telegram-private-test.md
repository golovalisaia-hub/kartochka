# Карточка — закрытый Telegram Mini App тест

Эта ветка предназначена только для закрытого тестирования. Она не изменяет `main`, не использует реальные номера карт и не принимает реальные платежи.

## Безопасные границы

* Telegram `initData` проверяется на сервере по HMAC с `TELEGRAM_BOT_TOKEN`; устаревшие, повторяющиеся и изменённые поля отклоняются.
* Логин создаёт отдельную тестовую учётную запись Telegram и выдаёт обычную Supabase-сессию только после серверной проверки подписи.
* Карты Telegram хранятся в `telegram_test_cards`, отдельно от production-таблицы `cards`. RLS разрешает чтение только владельцу.
* Каталог является отдельной проекцией. Для публикации принимаются только синтетические номера с префиксом `TEST-`; отзыв обмена удаляет проекцию, но не блокирует редактирование или удаление личной карты.
* Webhook принимает только запросы с `X-Telegram-Bot-Api-Secret-Token`, а `/start` показывает кнопку Mini App с тестовым HTTPS-адресом.
* `create-premium-invoice` намеренно отвечает `403`; Telegram Payments и любые покупки отключены.

## Секреты Supabase Edge Functions

В Supabase должны существовать только в Secrets (не в git и не в браузерном коде):

* `TELEGRAM_BOT_TOKEN`
* `TELEGRAM_WEBHOOK_SECRET`
* `TELEGRAM_WEB_APP_URL` — HTTPS-адрес отдельного staging-развёртывания.

`SUPABASE_SERVICE_ROLE_KEY` предоставляется Supabase Edge Functions автоматически и не должен добавляться в репозиторий.

## Настройка Telegram

После публикации функции нужно один раз вызвать `POST /functions/v1/telegram` с JSON `{"action":"setup"}` и заголовком `X-Telegram-Bot-Api-Secret-Token`, равным сохранённому `TELEGRAM_WEBHOOK_SECRET`. Функция сама устанавливает webhook, `/start`, кнопку меню и возвращает только обезличенный статус webhook.

Если BotFather ещё не настроен вручную, достаточно открыть `@BotFather`, выбрать `@KartochkaWalletBot` и задать:

1. `/setdescription` — кратко описать закрытый тест кошелька скидочных карт.
2. `/setcommands` — команду `start` с описанием «Открыть Карточку».
3. `/setmenubutton` — кнопку `Открыть Карточку` типа Web App с тем же staging HTTPS-адресом.

## Быстрый доступ и компактный режим

Подробности, включая разбор бага «открывается экран входа Vercel вместо Карточки», порядок
настройки Main Mini App и инструкции для жестов телефона — в
[`docs/telegram-quick-access.md`](./telegram-quick-access.md).

Коротко:

* Компактный экран включается только ссылкой `?startapp=quick&mode=compact`; из JavaScript
  задать компактную высоту нельзя.
* `expand()` не вызывается при запуске. Он срабатывает только внутри нажатия пользователя —
  при открытии полного списка или когда компактной высоты не хватает для штрихкода.
  Вернуться к компактной высоте программно Telegram не позволяет.
* `start_param` выбирает только экран. Он не даёт прав, не подтверждает личность и при
  неизвестном значении откатывается к обычному кошельку.
* До серверной проверки `initData` показывается нейтральный экран, а не чужие карты.

## Проверки

Локально запускаются:

* `node tests/telegram-private-test.cjs` — подпись, свежесть, приватность, версия SDK,
  отсутствие автоматического `expand()` и проверка адреса Mini App на чужую страницу входа;
* `node tests/telegram-browser-e2e.cjs` — вход, изолированное добавление/редактирование/удаление, штрихкод, повторное открытие, каталог и отключённые платежи;
* `node tests/telegram-quick-mode.cjs` — запуск `startapp=quick`, порядок недавних карт, код
  за одно нажатие, кнопка «Все карты», возврат и компактная вёрстка на пяти размерах экрана и высотах Telegram-шторки;
* `node tests/telegram-account-privacy.cjs` — изоляция аккаунтов, задержка и отказ входа,
  перенос истории открытий между устройствами, офлайн-очередь, tombstone и отсутствие ложных
  конфликтов при одновременных открытии и переименовании;
* существующий набор wallet/cloud/atomic регрессий.

Проверка реального Telegram-клиента требует тестового аккаунта и вымышленных карт. Не загружайте реальные карты и не объединяйте Telegram с production-кошельком до отдельной проверки миграции аккаунтов.
