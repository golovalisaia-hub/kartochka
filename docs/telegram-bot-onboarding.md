# Первое знакомство с «Карточкой» в Telegram

## Четыре разных уровня оформления

Их нельзя путать и нельзя реализовать одним экраном:

| Уровень | Чем задаётся | Что показывает |
| --- | --- | --- |
| Системная карточка до Start («Что умеет этот бот?») | `setMyDescription`, `setMyShortDescription`; картинка — только BotFather | описание бота |
| Приветственное сообщение после Start | `sendAnimation` / `sendPhoto` + `inline_keyboard` | обложка, текст, сетка кнопок |
| Разделы бота | `editMessageCaption` / `editMessageText` | инструкции, тарифы, поддержка |
| Mini App | Web App кнопка | полноценный кошелёк |
| Компактный Mini App | `?startapp=quick&mode=compact` | недавние карты |

## Навигация

После Start приходит одно сообщение: обложка, описание и сетка кнопок.

```
                       ┌──────────────────────┐
                       │   обложка (GIF/MP4)  │
                       │   описание           │
                       ├──────────────────────┤
  ➕ Добавить карту    │  →  Mini App, экран добавления (?startapp=add)
  💳 Открыть приложение│  →  Mini App, полный кошелёк
  ⚡ Кнопка действия   │  👆 Двойной тап      │  →  инструкции + ссылка на компактный кошелёк
  ⭐ Тарифы и Premium  │  🛟 Поддержка        │
                       └──────────────────────┘
```

Каждый информационный раздел возвращает на главный экран кнопкой «⌂ Главное меню».
Инструкции по жестам дополнительно ведут на экран «🤖 Android».

Команды: `/start` — приветствие с обложкой, `/menu` — тот же главный экран,
`/quick` — экран быстрого доступа, `/plans` — тарифы, `/support` — поддержка. Любая другая
команда открывает главный экран; на обычное сообщение бот один раз отвечает подсказкой.

Отдельного шага «Начать» больше нет: и новый, и постоянный пользователь попадает в кошелёк
одним нажатием прямо с приветствия. Кнопка `kartochka:features` из старых сообщений открывает
тот же главный экран.

## Аватар бота

Аватар — это **не** картинка блока «Что умеет этот бот?». Это два разных изображения.

Метода Bot API, которым бот менял бы себе аватар, исторически нет: это делает только
BotFather. Чтобы не гадать по документации, в функцию встроена безопасная проба живого API:

```
POST /functions/v1/telegram
X-Telegram-Bot-Api-Secret-Token: <TELEGRAM_WEBHOOK_SECRET>
{"action":"brand"}
```

Проба вызывает предполагаемые методы **без файла**, поэтому сменить аватар случайно не может.
Ответ `avatar.api_can_set` — фактический вердикт актуального Bot API. Если когда-нибудь метод
появится и задан источник, то же действие загрузит аватар и вернёт результат в `avatar.applied`.

Пока метода нет, порядок такой:

1. `@BotFather` → `/mybots` → `@KartochkaWalletBot` → `Edit Bot` → `Edit Botpic`.
2. Отправить `assets/branding/avatar-telegram.jpg` (квадратный JPG).

Telegram обрезает аватар в круг. Логотип и серебристое кольцо должны умещаться в круг,
вписанный в квадрат, иначе углы срежутся — запас по краям обязателен.

## Системная карточка до Start

`{"action":"setup"}` публикует её документированными методами Bot API:

* `setMyDescription` — полное описание (лимит 512 символов, используется 272);
* `setMyShortDescription` — короткое описание (лимит 120 символов, используется 72).

**Картинку этой карточки Bot API менять не умеет** — её задаёт только BotFather:

1. Откройте `@BotFather` → `/mybots` → `@KartochkaWalletBot`.
2. `Edit Bot` → `Edit Description Picture`.
3. Отправьте вашу обложку. Требования BotFather: квадратное изображение или короткое видео,
   не более 640×640.
4. Чтобы удалить её позже: `Edit Description Picture` → `/empty`.

Текст описания при этом трогать не нужно — его уже задаёт `setup`.

### Быстрый запуск не показывает презентацию

`https://t.me/KartochkaWalletBot?startapp=quick&mode=compact` открывает Mini App напрямую —
бот в этом не участвует и обучающие экраны не показываются. Deep link `/start quick` тоже
пропускает презентацию и сразу даёт кнопку запуска кошелька.

## Поведение кнопок

* «➕ Добавить карту» открывает то же Mini App с параметром `?startapp=add`: приложение
  показывает обычный кошелёк и сразу открывает лист добавления карты. Параметр выбирает только
  экран — он не даёт прав и не пропускает проверку `initData`; лист открывается лишь после
  того, как аккаунт подтверждён.
* Каждое нажатие подтверждается `answerCallbackQuery`, поэтому индикатор загрузки не зависает.
* Переходы **редактируют то же сообщение** (`editMessageText`, а для сообщения с фотографией —
  `editMessageCaption`), поэтому чат не засоряется.
* Повторное нажатие той же кнопки Telegram отклоняет с `message is not modified`. Это не
  ошибка: бот молча оставляет экран как есть и отвечает `200`, иначе Telegram повторял бы
  webhook снова и снова.
* Если сообщение устарело, удалено или подпись не помещается в лимит Telegram (1024 символа),
  бот отправляет новое сообщение вместо того, чтобы оставить кнопку мёртвой.
* Все экраны укладываются в 1024 символа — это проверяется тестом, чтобы любой экран можно
  было показать подписью под приветственной картинкой.
* Проверка доступности приложения кешируется на минуту, поэтому листание меню не обращается к
  сайту на каждое нажатие.

## Обложка приветственного сообщения

Материалы владельца не заменяются и не генерируются. Бот пробует источники по порядку и
запоминает первый, который принял Telegram:

| # | Метод | Источник |
| --- | --- | --- |
| 1 | `sendAnimation` | `TELEGRAM_WELCOME_ANIMATION_FILE_ID` |
| 2 | `sendAnimation` | `TELEGRAM_WELCOME_ANIMATION_URL` (публичный `.gif` или `.mp4`) |
| 3 | `sendPhoto` | `TELEGRAM_WELCOME_PHOTO_FILE_ID` |
| 4 | `sendPhoto` | `TELEGRAM_WELCOME_PHOTO_URL` |
| 5 | `sendAnimation` | `assets/branding/welcome.gif` |
| 6 | `sendAnimation` | `assets/branding/welcome.mp4` |
| 7 | `sendAnimation` | `welcome.mp4`, `welcome.gif` в корне репозитория |
| 8 | `sendPhoto` | `assets/branding/welcome.png`, `welcome.png` |

**Самый простой вариант: положите свою анимацию в `assets/branding/welcome.gif`.**
Больше ничего настраивать не нужно — адрес получается сам из адреса приложения.
Требования к файлам — в [`assets/branding/README.md`](../assets/branding/README.md).

Telegram показывает анимацию в её собственных пропорциях; файл передаётся как есть, ничего не
пережимается и не обрезается. Ограничения Telegram: до 10 МБ по URL, сумма сторон не больше
10000, соотношение сторон не более 20:1. Для `.mp4` нужен кодек H.264 без звуковой дорожки —
иначе Telegram покажет его как видео, а не как анимацию. Адрес должен открываться без входа:
за Vercel Deployment Protection Telegram файл не получит.

Если ни один источник не сработал, приветствие уходит текстом. Отрицательный результат
запоминается на 5 минут, поэтому добавленный позже файл подхватится сам и повторные `/start`
не дёргают Telegram заново.

**В репозитории сейчас нет ни анимации, ни приветственной иллюстрации** — только иконки
приложения (`icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, `icon.svg`). Как обложку
они не используются: это иконки, а не оформление.

Подпись под обложкой ограничена 1024 символами. Все экраны уложены в этот лимит, и это
проверяется тестом, поэтому предложения не обрезаются.

## Поддержка

Переменная `TELEGRAM_SUPPORT_URL` должна указывать на контакт вида `https://t.me/<аккаунт>`.
Адреса на других доменах отклоняются, чтобы кнопка не увела пользователя на посторонний сайт.
Пока контакт не задан, бот честно пишет, что связь не подключена, и называет переменную,
которую нужно задать, — он не обещает ответ на сообщения, которые некуда доставить.

Обращения пользователей бот никуда не пересылает и не логирует: серверная пересылка не
настроена, а придумывать чат администратора нельзя. Telegram ID пользователей другим
пользователям не показываются.

## Premium и тарифы

Раздел говорит прямо: кошелёк, добавление карт, поиск, штрихкоды и недавние карты бесплатны и
платными не станут. Premium — планируемая **однократная** покупка, не ежемесячная подписка;
стоимость уточняется, дата не определена. Обмен картами описан как добровольный, а бонусы за
чужие покупки не обещаются — это зависит от правил конкретного магазина. Кнопок оплаты нет,
Telegram Stars не подключены, `create-premium-invoice` отвечает `403`.

## Развёртывание

GitHub не публикует Edge Function автоматически. После прохождения CI нужно:

1. Опубликовать функцию `telegram` вместе с `_shared/telegram.ts` и `_shared/bot-onboarding.ts`.
2. Убедиться, что `TELEGRAM_WEB_APP_URL` открывается без авторизации (ссылка за Vercel
   Deployment Protection не подходит) — проверяется запросом `{"action":"diagnose"}`.
3. Вызвать `{"action":"setup"}` с заголовком `X-Telegram-Bot-Api-Secret-Token`. Операция
   переустанавливает webhook с `callback_query` в `allowed_updates` и обновляет список команд.

Без шага 3 кнопки навигации не работают: Telegram просто не присылает `callback_query`.

Значения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` не публикуются и не попадают в логи.
Старые сообщения сохраняют старые кнопки — отправьте `/start` заново. Кнопка `kartochka:plans`
из прежних сообщений продолжает работать и открывает «Premium и тарифы».

Тесты: `node tests/telegram-onboarding.cjs` плюс полный набор GitHub Actions. Работа на реальном
Telegram-клиенте и изображение владельца автоматическими тестами не подтверждаются.
