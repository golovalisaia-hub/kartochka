# «Карточка»: вместо кода приходит ссылка

## Подтверждённый симптом

Письма доходят до пользователя, но содержат ссылку, а приложение ожидает **цифровой одноразовый код**. Значит, сначала необходимо исправить **шаблоны писем**, а не менять SMTP только из-за этого симптома. Вход с паролем не нужен.

## Настройка в Supabase (владелец проекта)

1. Откройте [Email Templates проекта «kartochka»](https://supabase.com/dashboard/project/cwiechastoocixpnobuy/auth/templates).
2. Откройте **Magic Link / OTP**. Вместо шаблона, содержащего только `{{ .ConfirmationURL }}`, вставьте шаблон ниже и сохраните.
3. **Обязательно откройте Confirm signup** и поставьте такой же шаблон: впервые входящий пользователь может получать отдельное письмо подтверждения, а не Magic Link. Это позволит ввести цифровой код и при первой регистрации.
4. Убедитесь, что **Authentication → Providers → Email** включён. Не отключайте проверку почты ради обхода проблемы.
5. Запросите **один** новый код в «Карточке». Старое письмо со ссылкой не превратится в письмо с цифрами. Введите новый код в приложении и проверьте вход тестового аккаунта. Не публикуйте адрес почты, одноразовый код, SMTP-пароль или сервисные ключи.

**Шаблон для обоих писем:**

```html
<h2>Код для входа в Карточку</h2>
<p>Ваш одноразовый код: <strong>{{ .Token }}</strong></p>
<p>Если вы не запрашивали код, проигнорируйте это письмо.</p>
```

В проекте должен остаться только **публичный** ключ в `config.js`. Не вставляйте секреты в GitHub или браузерные скрипты.

## Когда действительно нужен SMTP

Если **письмо не приходит на другие адреса** и Supabase сообщает `Email address not authorized`, это отдельное ограничение встроенной SMTP-службы: она разрешает отправку только членам команды проекта. Для регистрации произвольных пользователей потребуется собственный почтовый отправитель в [Supabase → Authentication → SMTP Settings](https://supabase.com/dashboard/project/cwiechastoocixpnobuy/auth/smtp). Наличие у нынешнего пользователя письма со ссылкой **не доказывает**, что SMTP уже настроен для всех.

Успешный ответ API означает лишь, что запрос обработан, но не гарантирует доставку. Повторная отправка ограничена таймером, чтобы не расходовать лимиты.
