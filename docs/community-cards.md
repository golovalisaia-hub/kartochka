# Карты сообщества

Личный кошелёк «Карточки» остаётся бесплатным. Раздел сообщества — отдельная надстройка:
владелец добровольно разрешает показывать свою карту, а участник с Premium получает по
запросу одну карту выбранного магазина, не зная, чья она.

Реальная оплата Premium не подключена. Флаг `premium_payments_enabled` выключен, кнопок
оплаты нет, Telegram Stars не используются.

## Согласие владельца

Общий доступ **всегда выключен по умолчанию**. Включить его может только владелец и только
явным действием:

1. После сохранения карты поддерживаемого магазина появляется блок «Получайте больше пользы
   от своей карты» с кнопкой «Поделиться картой» и знаком `?`.
2. `?` открывает объяснение: показ добровольный, начисления зависят от правил магазина,
   показы распределяются равномерно, доступ отключается в любой момент. Никаких обещаний
   гарантированных баллов.
3. «Поделиться картой» открывает подтверждение с перечнем последствий. Заранее отмеченных
   галочек нет. Только нажатие «Разрешить» действительно включает доступ.
4. «Не сейчас» запоминается в `kartochka.sharing-offer-dismissed.v1`, и предложение больше не
   всплывает при каждом открытии карты. Включить доступ позже можно из той же карточки.

После включения владелец видит агрегаты: «Показана сегодня», «За 7 дней», «Всего показов»,
«Последний показ» и кнопку «Отключить общий доступ». Слово «покупка» не используется — данных
кассы у приложения нет, известен только факт показа.

Отключение действует немедленно: `sharing_enabled = false`, новые выдачи прекращаются.
Удаление карты убирает её из пула автоматически — выдаются только карты, у которых исходная
запись жива (`deleted_at is null`).

## Схема

| Таблица | Назначение |
| --- | --- |
| `loyalty_programs` | программы и их правила: пределы, перерывы, разогрев, TTL сессии |
| `loyalty_brand_contexts` | магазины внутри программы: у X5 единый счёт, но разные бренды |
| `shared_cards` | согласие владельца и суммарные счётчики |
| `shared_card_serves` | журнал показов, из него считаются окна 24 ч и 7 дней |
| `shared_card_sessions` | короткий доступ подписчика к одной выданной карте |
| `subscriptions` | состояние Premium; менять может только серверная функция |
| `payment_events` | идемпотентность будущих платёжных событий |
| `community_requests` | обращения: нужны для ограничения частоты и метрик |
| `community_audit` | аудит без номеров карт и штрихкодов |
| `feature_flags` | переключатели, включая аварийный |

X5 Клуб заведён как одна программа `x5_club` с брендами `pyaterochka` и `perekrestok`:
пользователь выбирает конкретный магазин, а система понимает, что счёт лояльности общий.
Лента — отдельная программа `lenta`. Правила лежат в таблице, а не в коде приложения.

## Premium и entitlement

Единственная точка истины — `has_community_access(user)`: подписка со статусом `active` и не
истёкшим сроком. Её вызывает `claim_shared_card` при каждом запросе. Клиент лишь отображает
состояние и не может открыть доступ подделкой — RPC всё равно вернёт `denied`.

Прав на запись в `subscriptions` нет ни у кого из клиентских ролей. Тестовый Premium выдаётся
только серверной функцией `grant_test_subscription`, недоступной роли `authenticated`.

Будущая оплата подключается по цепочке: платёж → проверенный серверный webhook →
`subscriptions.status = 'active'` → `has_community_access` → вкладка открывается. Ответам
клиента, redirect-страницам и `localStorage` доверия нет. Идемпотентность обеспечивает
уникальность `(provider, provider_event_id)` в `payment_events`.

## Честное распределение показов

`claim_shared_card` отбирает карту строго по порядку:

1. меньше показов за 24 часа — основное окно;
2. меньше показов за 7 дней;
3. самый давний показ, карты без показов идут первыми;
4. случайный выбор при полном равенстве.

`served_total` в отборе **не участвует**: иначе новая карта получала бы весь поток, догоняя
старые. Он остаётся статистикой для владельца.

Из ротации карта временно выпадает, если сработал перерыв (`cooldown_seconds`), перерыв для
того же подписчика (`subscriber_cooldown_seconds`), дневной предел карты
(`per_card_daily_limit`) или дневной предел программы (`daily_usage_limit`). Свежая карта
ограничена `warmup_max_serves` в течение `warmup_hours`, чтобы войти в ротацию плавно, а не
забрать весь поток.

## Атомарность

Отбор, запись показа, обновление счётчиков и создание сессии выполняются **в одной
транзакции**, а строка берётся с `for update ... skip locked`. Разделить шаги нельзя: между
`select` и `update` два параллельных запроса выбрали бы одну карту, счётчики разошлись бы с
журналом и честность сломалась бы.

Проверено на настоящем PostgreSQL: `bash tests/sql/community-concurrency-check.sh` запускает
10 одновременных запросов к пулу из 5 карт и требует, чтобы счётчики совпали с журналом, на
каждую выдачу пришлась сессия, а разброс показов между картами не превысил двух.

## Приватность и RLS

Подписчик не видит владельца, владелец не видит подписчика. В ответе `claim_shared_card` нет
ни идентификатора, ни имени, ни контакта владельца — только данные карты.

`shared_cards` читается только владельцем собственных строк: выгрузить пул запросом нельзя
даже с активным Premium. Журнал показов и обращений не читается клиентскими ролями вообще.
Единственный путь к чужой карте — `claim_shared_card`.

Ограничение частоты: не более 10 обращений в минуту и 60 в час на пользователя. Превышение
возвращает `rate_limited`, не раскрывая состояние пула.

Номера карт не попадают в аудит, в журнал обращений, в адреса и в сообщения об ошибках.
Отказы возвращаются нейтральными кодами (`no_card`, `denied`, `disabled`, `rate_limited`), без
внутренних причин.

## Переключатели

| Флаг | Действие |
| --- | --- |
| `community_kill_switch` | гасит весь раздел; личный кошелёк продолжает работать |
| `community_access_enabled` | выдача карт подписчикам |
| `community_sharing_enabled` | включение общего доступа владельцами |
| `x5_community_enabled` | отключает X5, не трогая Ленту |
| `lenta_community_enabled` | отключает Ленту, не трогая X5 |
| `premium_payments_enabled` | реальная оплата; выключен |

Ни один переключатель не удаляет карты пользователей.

## Проверки

```
psql -d <база> -v ON_ERROR_STOP=1 -f tests/sql/community-cards-check.sql
bash tests/sql/community-concurrency-check.sh
node tests/community-ui.cjs
```

Первый файл проверяет право доступа, согласие, точный порядок ротации, пределы, перерывы,
аварийный выключатель и RLS. Второй — параллельность. Третий — поведение интерфейса.
