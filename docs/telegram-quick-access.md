# Быстрый доступ к картам через Telegram

## Найденная причина бага «открывается сайт вместо Карточки»

При нажатии «Открыть Карточку» в боте Telegram показывал экран **Log in to Vercel** внутри
окна с заголовком «Карточка».

Бот, кнопка меню и Mini App были настроены правильно. Проблема в самом адресе, который
хранится в серверной переменной `TELEGRAM_WEB_APP_URL`: он указывает на развёртывание Vercel,
у которого включена **Deployment Protection (Vercel Authentication)**. Telegram открывает этот
адрес в своём WebView как обычный браузер, Vercel отвечает своей страницей входа — и
пользователь видит форму Vercel вместо приложения.

Telegram здесь ни при чём: `setChatMenuButton` принимает любой HTTPS-адрес и не проверяет,
что по нему отвечает. Поэтому проверка добавлена в наш код.

### Что нужно сделать (требуется доступ к Vercel или смена адреса)

Вариант 1 — снять защиту с развёртывания:

1. Vercel → проект «Карточка» → **Settings** → **Deployment Protection**.
2. **Vercel Authentication** → переключить в **Disabled**.
3. Сохранить и открыть адрес в приватном окне браузера: должна открыться «Карточка».

Вариант 2 — использовать публичный адрес (GitHub Pages), который не требует входа:
задать `TELEGRAM_WEB_APP_URL` равным адресу GitHub Pages этого репозитория.

После этого один раз вызвать настройку бота (см. ниже). Она больше не позволит записать
в Telegram адрес, который отвечает чужой страницей входа.

### Как проверить, не раскрывая секретов

```
POST https://<supabase-project>.supabase.co/functions/v1/telegram
X-Telegram-Bot-Api-Secret-Token: <TELEGRAM_WEBHOOK_SECRET>
Content-Type: application/json

{"action":"diagnose"}
```

Ответ показывает только факты, без значений секретов:

* `web_app_url.serving_app` — отвечает ли адрес именно «Карточкой»;
* `web_app_url.reason` — например `vercel-deployment-protection`;
* `web_app_url.hint` — что именно переключить;
* `secrets.*` — только `true`/`false`, существует ли секрет;
* `webhook.url_matches`, `menu_button.opens_app`.

Настройка бота (webhook, команды, кнопка меню) — тот же запрос с `{"action":"setup"}`.
Если адрес закрыт страницей входа, `setup` вернёт `409` и **не** тронет настройки бота.

## Три независимых способа запуска

Это разные механизмы. Успешная проверка одного ничего не говорит об остальных.

| Способ | Что настраивается | Что открывает |
| --- | --- | --- |
| Кнопка в профиле бота | BotFather → Main Mini App | обычный кошелёк |
| Кнопка меню в чате | `setChatMenuButton` (или BotFather `/setmenubutton`) | обычный кошелёк |
| Прямая ссылка | `https://t.me/KartochkaWalletBot?startapp=quick&mode=compact` | компактный экран |

Про кнопку меню: Bot API допускает в `MenuButtonWebApp.web_app.url` и прямой HTTPS-адрес
приложения, и поддерживаемую `t.me`-ссылку на Mini App того же бота. Сейчас используется
HTTPS-адрес, потому что оба варианта в итоге грузят один и тот же адрес приложения, а прямой
HTTPS-адрес можно проверить автоматически (см. `inspectWebAppUrl`) — у `t.me`-ссылки такой
проверки нет. Кнопка меню по умолчанию открывает обычный кошелёк и **не** наследует
`mode=compact` от прямой ссылки.

`mode=compact` — параметр ссылки запуска, а не настройка, которую Mini App может установить
из JavaScript. Поэтому компактная высота достигается только переходом по прямой ссылке.

## Настройка Main Mini App в BotFather

1. Открыть `@BotFather` → `/mybots` → `@KartochkaWalletBot`.
2. `Bot Settings` → `Configure Mini App` → `Enable Mini App`.
3. Указать HTTPS-адрес приложения (тот же, что в `TELEGRAM_WEB_APP_URL`).
4. Проверить, что в профиле бота появилась кнопка запуска приложения.

Только после этого ссылка `?startapp=quick` начнёт работать как Main Mini App.
`startapp` — это не то же самое, что параметр команды `/start`.

## Жесты телефона

Ссылка для всех вариантов одна:

```
https://t.me/KartochkaWalletBot?startapp=quick&mode=compact
```

### iPhone — двойное касание задней панели

1. «Команды» (Shortcuts) → «+» → «Добавить действие» → **Открыть URL** → вставить ссылку.
2. Назвать команду «Карточка», сохранить.
3. Настройки → Универсальный доступ → Касание → Касание задней панели → Двойное касание →
   выбрать «Карточка».

Названия пунктов отличаются между версиями iOS. iOS может показать подтверждение открытия
ссылки — это реальный дополнительный шаг, обходить его нельзя. Запуск с заблокированного
экрана не подтверждён.

### iPhone — кнопка «Действие»

Та же команда: Настройки → Кнопка «Действие» → «Быстрая команда» → выбрать «Карточка».
Кнопка есть не на всех моделях. Двойное нажатие обычной боковой кнопки на Mini App
переназначить нельзя.

### Android

* Универсально и надёжно: открыть ссылку в браузере → «Добавить на главный экран» → ярлык.
* Pixel: Настройки → Система → Жесты → Quick Tap. Если система предлагает только приложения,
  то откроется Telegram, а не компактный кошелёк.
* Samsung: Настройки → Дополнительные функции → Боковая кнопка → Двойное нажатие.

Системные жесты Android часто умеют запускать только приложение, а не конкретную ссылку.
Пока это не проверено на конкретной модели, нельзя утверждать, что жест открывает Mini App.

## История открытий: что изменилось в данных

Старое поле `lastUsed` записывалось и при **создании** карты, и при её **открытии**. Поэтому
его прошлые значения нельзя выдавать за историю открытий: только что добавленная карта
оказывалась первой, хотя пользователь её ни разу не открывал.

Миграция сделана без потерь:

* `openedAt` (в базе `last_opened_at`) считает **только реальные открытия** и у существующих
  карт начинается с пустого значения;
* старое значение сохранено как `legacyTouchedAt` и используется лишь как дополнительный
  порядок между картами, которые никогда не открывались;
* само `lastUsed` не тронуто — старые клиенты и резервные копии продолжают работать.

Ограничение, которое важно понимать: **историю открытий до этого изменения восстановить
нельзя**, потому что приложение её не записывало. Первые открытия появятся после обновления.

Порядок сортировки: сначала карты с подтверждённым открытием (по убыванию), затем карты без
истории, при равенстве — стабильный порядок по идентификатору.

Проверить поведение миграции можно на локальном PostgreSQL (в браузерном CI базы нет):

```
createdb kartochka_check
psql -d kartochka_check -v ON_ERROR_STOP=1 -f tests/sql/open-history-check.sql
```

Скрипт падает с ошибкой, если пользователь смог поставить отметку чужой карте, если удалённая
карта приняла историю, если изменилась `revision` или если время поехало назад.

Открытие карты синхронизируется отдельным вызовом `record_*_card_opens`, который меняет только
`last_opened_at` у строк текущего пользователя и **не трогает `revision`**. Поэтому открытие
на одном устройстве доходит до другого и при этом не превращается в ложный конфликт
редактирования. Открытие без сети остаётся в очереди в localStorage и повторяется при
следующей успешной синхронизации.
